# v1.9.0 Release-Candidate Baseline

This document records the v1.9.0 release-candidate baseline before release preparation. It consolidates the recent hardening checks without performing release preparation work.

## Scope

v1.9.0 remains focused on release-candidate hardening for the existing React Three Fiber phase-flow package. This baseline covers package entrypoint behavior, public type export clarity, package metadata alignment, documentation readiness, dry-run publish contents, and focused release-candidate bug triage.

The package version is not changed by this documentation task.

## Verified areas

Recent hardening verified:

- package entrypoint runtime exports for `FlowProvider`, `useFlow`, `useFlowProgress`, `useFlowFrame`, `useWheelInput`, `useTouchInput`, and `useKeyboardInput`
- explicit public type exports for the documented provider, frame bridge, transition options, and input hook types
- root-only package exports with no internal subpath exports
- package metadata alignment with generated root entrypoint artifacts
- absence of accidental runtime dependencies
- peer dependency scope for React, React DOM, Three.js, and React Three Fiber
- package entrypoint import guidance in README and example documentation
- DOM/client hook boundaries compared with Canvas-bound `useFlowFrame` usage
- Next.js Client Component compatibility boundary without adding Next.js as a dependency or providing router integration

## Documentation readiness

The root README, package README, and Vite example README were checked for v2.0.0 readiness wording around the current v1.9.0 release-candidate surface.
