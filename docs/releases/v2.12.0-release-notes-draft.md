## GitHub Release draft

# r3f-interactive-flow v2.12.0

### Highlights

`v2.12.0` is a focused, backward-compatible runtime/input resilience release.
The completed v2 runtime, React lifecycle, and R3F ownership boundaries were
re-audited after v2.11.1. The audit found one concrete DOM wheel-event
robustness defect and no evidence justifying broader runtime or API expansion.

No migration is required.

### Non-cancelable wheel-event prevention

`useWheelInput` now requests native-event prevention for an accepted wheel
event only when prevention is enabled and the event is not explicitly
non-cancelable.

Navigation acceptance remains independent of `event.cancelable`. An accepted
explicitly non-cancelable wheel event still navigates; the hook simply avoids an
ineffective `preventDefault()` call for that event.

### Preserved behavior

- Accepted cancelable wheel events retain configured prevention.
- Rejected wheel navigation remains unprevented.
- `preventDefault: false` remains unchanged.
- Wheel threshold, axis, normalization, burst, cooldown, target, ignore,
  rerender, and cleanup contracts are unchanged.
- Touch and keyboard behavior are unchanged.
- Provider cooldown and hook-local cooldown remain separate.
- The provider remains the single machine-advancing clock owner.
- `useFlowFrame` remains read-only and Canvas-bound.
- Public runtime exports, public types, package exports, runtime dependencies,
  peer ranges, and package structure remain unchanged.

### Documentation

PR #488 aligned the package README and maintained input guide with the corrected
wheel behavior. Wheel and touch cancelability now share the high-level rule
that cancelability controls prevention eligibility, not navigation acceptance,
while touch-only committed-gesture semantics remain documented separately.

### Compatibility and migration

This is a backward-compatible minor release with no public API migration. No
export, dependency, peer-range, option, or package-subpath change is included.
