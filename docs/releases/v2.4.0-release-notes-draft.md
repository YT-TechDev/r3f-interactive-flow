# r3f-interactive-flow v2.4.0

v2.4.0 focuses on runtime correctness, predictable browser input, stable React
provider behavior, and a safer npm release path.

### Highlights

- `FlowProvider` now separates stable machine access from reactive snapshots,
  avoiding unnecessary frame-by-frame React re-renders for `useFlowFrame()`
  consumers.
- Provider cooldown now begins after transition completion, so the full
  configured cooldown remains meaningful.
- Wheel, keyboard, and touch events suppress native browser behavior only when
  flow navigation is accepted.
- Unresolved explicit input refs no longer broaden their listener target to
  `window`.
- Wheel input now normalizes pixel, line, and page delta modes and accumulates
  high-resolution trackpad input into one deterministic navigation per burst.
- Equivalent parent renders preserve the mounted `FlowProvider` machine.
  Intentional reconfiguration uses a React `key` remount.
- The release path now supports npm Trusted Publishing through GitHub Actions
  OIDC with automatic provenance and no long-lived npm publishing token.

### Behavior changes

- Cooldown starts at the transition-completion boundary instead of navigation
  acceptance.
- Zero-duration transitions complete synchronously and immediately enter their
  configured cooldown.
- Rejected input, boundaries, locks, cooldowns, active transitions, editable
  elements, and actionable controls retain native browser behavior.
- Material `FlowProvider` configuration changes do not replace the machine
  during the mounted provider lifetime. Use a React `key` remount when an
  intentional reset or reconfiguration is required.

### Compatibility

There are no public API additions or removals, no new runtime dependencies, no
peer dependency range changes, and no package export changes.

The release contains intentional behavior corrections for cooldown timing,
browser event consumption, wheel gestures, and provider reconfiguration. Users
depending on the previous edge-case behavior should review these areas.
