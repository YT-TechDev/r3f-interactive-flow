# v2.0.0 Package Exports Audit

## Scope

This audit finalizes package export and publish-boundary readiness for v2.0.0. It covers package metadata, build entry configuration, the root source entrypoint, focused public API tests, package README import guidance, and the recent release audit records listed for this task.

This audit does not change source behavior, tests, package metadata, package exports, package version, dependencies, examples, or release automation.

## Export metadata

Package metadata remains aligned with the generated root entrypoint artifacts:

- `main` points to `./dist/index.cjs` for CommonJS consumers.
- `module` points to `./dist/index.js` for ESM consumers.
- `types` points to `./dist/index.d.ts` for TypeScript consumers.
- `exports["."]` maps `types`, `import`, and `require` to the same generated root artifacts.

The build configuration uses `src/index.ts` as the only entry and emits ESM, CJS, and declaration artifacts. No package subpath export is configured.

## Publish boundary

The `files` allowlist intentionally limits published contents to:

- `dist`
- `README.md`
- `LICENSE`
- `CHANGELOG.md`

No runtime `dependencies` field is present. Peer dependencies remain limited to:

- `react`
- `react-dom`
- `three`
- `@react-three/fiber`

## Consumer import boundary

Consumers should import the intended API from the package root:

```ts
import {
  FlowProvider,
  useFlow,
  useFlowProgress,
  useFlowFrame,
  useWheelInput,
  useTouchInput,
  useKeyboardInput
} from "r3f-interactive-flow";
```

Internal module paths such as `r3f-interactive-flow/react`, `r3f-interactive-flow/r3f`, and `r3f-interactive-flow/input` are not public package exports.

Focused entrypoint tests already cover the exact runtime export surface, explicit type exports, root-only package exports, package metadata alignment, allowed publish files, absence of runtime dependencies, and peer dependency names.

## Out-of-scope confirmation

This audit does not introduce:

- public API expansion
- package metadata changes
- package export changes
- source code changes
- test changes
- runtime dependency changes
- Next.js as a dependency
- router integration
- visual effects, animation timelines, camera presets, shader APIs, particle APIs, templates, CLI/codegen, or third-party animation wrappers
- npm publishing, git tags, GitHub Releases, or milestone closeout work

No shared AI chat, session, or task links are included.

## Result

The package remains centered on the root entrypoint and is ready for the v2.0.0 package export boundary. No release-blocking package export issue was found, and no metadata, source, test, dependency, or public API change is required for this task.
