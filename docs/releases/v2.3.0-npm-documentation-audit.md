# v2.3.0 npm documentation audit

This audit records the documentation surface that is distributed with the
`r3f-interactive-flow` npm package and how it relates to the GitHub-only user
guides added for the v2.3.0 documentation foundation.

## Package allowlist

`packages/r3f-interactive-flow/package.json` limits published package contents
with the `files` allowlist:

- `dist`
- `README.md`
- `LICENSE`
- `CHANGELOG.md`

npm also includes package metadata such as `package.json`. The allowlist does
not include repository-level documentation directories such as `docs/`.

## npm-distributed documentation

The package-facing documentation intended to ship to npm is:

- `packages/r3f-interactive-flow/README.md`
- `packages/r3f-interactive-flow/CHANGELOG.md`

The package README remains useful when viewed from npm because it documents the
stable package-root imports, peer dependencies, setup model, usage recipes,
Canvas-bound hook boundaries, input hooks, and package non-goals without relying
on repository-local guide files.

The package README references `CHANGELOG.md` as release history. That link is
safe for npm because `CHANGELOG.md` is included in the package allowlist and was
present in the package dry-run contents.

## GitHub-only documentation

The user-facing guides under `docs/guides/*` are repository documentation. They
are useful for GitHub readers, contributors, and AI coding agents, but they are
not currently included in the npm package.

GitHub-only guide files include:

- `docs/guides/README.md`
- `docs/guides/getting-started.md`
- `docs/guides/core-concepts.md`
- `docs/guides/r3f-usage.md`
- `docs/guides/input-handling.md`
- `docs/guides/nextjs-usage.md`
- `docs/guides/common-mistakes.md`

The root `README.md` can link to `docs/guides/README.md` because it is rendered
in the repository. The package README should not use relative links such as
`../../docs/guides/*`, because those files are not packed and those links would
be broken from npm.

## Link safety

No package README link cleanup was required for this audit.

The npm-distributed docs do not currently point to unpackaged repository guide
files. If the package README later links to the GitHub user guides, it should use
an absolute GitHub URL so the link remains valid from npm.

## Package dry-run result

The package dry-run was run with:

```bash
pnpm --filter r3f-interactive-flow pack:dry-run
```

The existing script ran `pnpm build && npm pack --dry-run` and reported
`r3f-interactive-flow@2.2.0` with 10 packed files:

- `CHANGELOG.md`
- `LICENSE`
- `README.md`
- `dist/index.cjs`
- `dist/index.cjs.map`
- `dist/index.d.cts`
- `dist/index.d.ts`
- `dist/index.js`
- `dist/index.js.map`
- `package.json`

The dry-run reported a package size of 34.2 kB and an unpacked size of 192.8 kB.
No `docs/guides/*` files were included.

## Decision

Keep the npm documentation surface limited to the package README and changelog
for now. Do not expand the package contents to include `docs/guides/*` unless a
clear user-facing npm need is identified.

This keeps the published package small, avoids broken relative links from npm,
and preserves the current split between npm-facing package docs and broader
GitHub repository guides.

## Scope confirmation

This audit is documentation-only. It does not change source behavior, public API,
package exports, package metadata, dependencies, lockfiles, or package version.
