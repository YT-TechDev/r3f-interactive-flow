# r3f-interactive-flow v2.7.0

v2.7.0 is an accessibility-responsibility, reduced-motion-guidance, and focused
browser-evidence minor release. It validates and documents application-owned
controls, native keyboard behavior, reduced-motion integration, and a
representative usage experience while preserving the stable v2 runtime API,
public types, package exports, dependencies, and peer dependency ranges.

### Highlights

- Records the package/application responsibility contract from #389.
- Records reduced-motion and provider-remount validation from #390.
- Records the focused Chromium input smoke from #383 and keyboard/native activation validation from #391.
- Records representative application patterns from #392.
- Records user-facing accessibility and reduced-motion guidance from #393.

### Responsibility boundary

Visible native controls are the baseline way to operate an experience. Input hooks are optional enhancements around the same phase controls, not the only operation path.

Applications own controls, labels, ARIA, disabled and current states, focus order and focus restoration, status wording, responsive layout, nested-scroll CSS, target sizing, and motion preference policy. The package does not render UI, move focus, create announcements, provide automatic ARIA, or certify an application experience.

### Reduced-motion integration

Reduced motion remains application-owned policy built with existing APIs. `duration: 0` is one valid app choice for flow transitions, not a mandatory or universally correct accessibility requirement. A short non-zero reduced duration is also valid when it better fits the application.

Provider timing and Canvas scene motion are separate. Changing provider transition timing does not automatically reduce scene, camera, shader, particle, CSS, or other motion; applications should adjust those surfaces separately.

Provider configuration is mount-scoped. An intentional keyed remount applies changed provider configuration and resets provider state, including phase, progress, transition, lock, and cooldown state. Applications decide whether that reset is acceptable and how to preserve or restore application-owned state and focus.

### Keyboard and native browser evidence

The bounded browser evidence uses one Vitest Browser Mode file with one Playwright-managed headless Chromium. It covers native button, anchor, checkbox, and editable targets; accepted-navigation prevention; repeated keyboard input; DOM ancestry for actionable/editable descendants; and focus non-interference.

Visible native controls work without `useKeyboardInput`, reinforcing that keyboard shortcuts are optional enhancements rather than the baseline operation path.

### Representative usage experience

The representative consumer demonstrates one application-owned usage pattern with visible controls, discrete status, focus-visible styles, nested scrolling, responsive targets, and normal/reduced motion modes. It is not a design system, template, accessibility certification suite, or universal solution.

### Documentation

The new guide documents package-root recipes, visible controls, input hook placement, native browser preservation, keyed remount, provider state reset, nested scrolling, reduced provider timing, and separate Canvas motion. Stale deferred-Chromium wording was corrected after the focused browser input smoke landed.

### Compatibility

- No runtime source changes in v2.7.0 milestone work.
- No public API or public type changes.
- No export or package-subpath changes.
- No runtime dependency or peer-range changes.
- The root-only package boundary remains unchanged.
- Browser tooling remains root development tooling only.

### Evidence boundaries

This release does not claim formal accessibility compliance, WCAG conformance, screen-reader validation, cross-browser certification, physical-device proof from automation, automatic focus or ARIA behavior, package-owned `prefers-reduced-motion` or `matchMedia` behavior, a reduced-motion hook, or universal correctness of `duration: 0`.
