# v2.0.0 Release Notes Draft

## Status

This is a draft for the future v2.0.0 GitHub Release. It does not announce that v2.0.0 is released.

This draft does not perform npm publishing, git tagging, GitHub Release creation, or milestone closeout. It also does not change source behavior, package metadata, package exports, package version, public API, tests, examples, or dependencies.

## Highlights

v2.0.0 is expected to be a stabilization and documentation release, not a feature expansion release. The release is focused on public API clarity, package boundary confidence, README accuracy, and migration guidance.

Completed readiness areas include:

- stable public API audit for the package root runtime exports and documented public type exports
- package exports audit for the root-only package boundary and publish allowlist
- README finalization for current usage, peer dependencies, Client Component guidance, and non-goals
- migration guide for moving from the latest v1.x release to v2.0.0

The v1.9.0 release-candidate baseline also recorded supporting hardening work:

- package entrypoint runtime export audit
- public type export audit
- package metadata audit
- package dry-run validation
- release-candidate bug triage

## Public API

The public runtime API remains centered on imports from the package root:

```ts
import {
  FlowProvider,
  useFlow,
  useFlowProgress,
  useFlowFrame,
  useWheelInput,
  useTouchInput,
  useKeyboardInput
} from "r3f-interactive-flow";
```

No public API expansion is included in the completed v2.0.0 readiness work. The package remains focused on `FlowProvider`, flow state hooks, the Canvas-bound `useFlowFrame` bridge, and optional wheel, touch, and keyboard input hooks.

No breaking public API or package export change is currently expected from the completed audits. Users importing from the package root should not need code changes for the documented public API, but application-specific integrations should still be reviewed.

## Package boundary

The package remains a root-entrypoint package. Consumers should import from `r3f-interactive-flow`, not internal package paths such as `r3f-interactive-flow/react`, `r3f-interactive-flow/r3f`, or `r3f-interactive-flow/input`.

The package exports audit confirmed the expected ESM, CommonJS, and TypeScript declaration entrypoints for the root package export. It also confirmed that published files remain limited to the intended package output and documentation files.

## Migration

Migration from the latest v1.x release to v2.0.0 is expected to be non-breaking for users of the documented package root API.

Recommended update command:

```bash
pnpm add r3f-interactive-flow@2.0.0 three @react-three/fiber react react-dom
```

Applications should continue to install `react`, `react-dom`, `three`, and `@react-three/fiber` as peer dependencies. Next.js is not a dependency.

Before updating, review the migration guide and verify that the application:

- imports documented APIs from `r3f-interactive-flow`
- avoids internal package subpath imports
- renders `FlowProvider` and flow hooks from client-side React components
- calls `useFlowFrame` only from Canvas-bound React Three Fiber components
- keeps browser input hooks in DOM/input layer components by default

## Scope

v2.0.0 readiness work does not add:

- public API expansion
- runtime dependencies
- Next.js as a dependency
- router integration
- visual presets or visual effects collections
- camera presets
- shader APIs
- particle APIs
- animation timelines
- templates
- CLI/codegen
- third-party animation wrappers

## Validation before release

Before the eventual v2.0.0 release, run the full release validation separately from this documentation draft. Expected checks include package build, package verification, typecheck, tests, lint, formatting, example build, and package dry-run validation.

This draft does not replace the separate release validation task and does not prepare the package for publication.
