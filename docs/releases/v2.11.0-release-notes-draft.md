## GitHub Release draft

# r3f-interactive-flow v2.11.0

### Highlights

v2.11.0 is a focused, backward-compatible flow-runtime-completion release.
The existing provider cooldown previously blocked navigation without exposing
that readiness boundary through `useFlow()`. The additive `isCoolingDown`
field now makes machine-wide provider cooldown observable without changing
navigation results, DOM input behavior, or the R3F frame bridge.

```ts
const { isCoolingDown } = useFlow();
```

No migration is required.

### Provider cooldown readiness

`FlowSnapshot<TPhase>`, `FlowControls<TPhase>`, and `useFlow<TPhase>()` expose
`isCoolingDown: boolean` with these semantics:

- A positive-duration transition exposes provider cooldown after transition
  completion.
- Accepted zero-duration navigation may expose provider cooldown
  synchronously.
- A zero cooldown keeps `isCoolingDown` false.
- Manual lock remains independent. Cooldown continues to expire while locked,
  and lock can remain active after cooldown expires.
- `isCoolingDown` returns to false at cooldown expiry.

Provider cooldown is machine-wide and rejects navigation from controls and all
input hooks while active. Hook-local wheel, touch, and keyboard cooldown is a
separate input concern and never changes `isCoolingDown`.

For UI readiness that covers all provider-owned rejection boundaries, use:

```ts
const disabled = isTransitioning || isCoolingDown || isLocked;
```

### Runtime boundaries

The provider remains the single owner of the machine-advancing clock.
Cooldown-only frames synchronize React state at the discrete start and expiry
boundaries rather than causing per-frame React updates.

DOM wheel, touch, and keyboard behavior is unchanged. `FlowFrameState` and
`useFlowFrame` remain read-only and unchanged, so the R3F boundary is also
unchanged. `useFlowProgress`, boolean navigation results, runtime exports,
named root type exports, package exports, peer ranges, runtime dependencies,
scripts, and CI remain unchanged.

### Compatibility and migration

This release is additive and backward-compatible. No legacy or deprecated
option was removed. Existing consumers do not need to change their code, and
no migration is required.
