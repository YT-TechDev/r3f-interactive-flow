## GitHub Release draft

# r3f-interactive-flow v2.10.0

### Highlights

v2.10.0 is a focused mature-v2 maintenance baseline. It preserves the
completed v2.9.0 public and runtime contract while recording the completed
audit evidence, package measurements, compatibility policy, legacy decisions,
and final validation for continued v2 maintenance.

This release adds no runtime feature, makes no breaking change, and requires
no migration.

### Mature v2 baseline

The completed baseline audit covered architecture, transition and input
behavior, frame bridging, package boundaries, security posture, and rollback
safety. It found no confirmed runtime or architecture blocker. These results
are audit evidence for the established implementation, not new runtime
behavior.

### Public API and package boundary

- The package exposes the intended seven runtime exports and eight named root
  type exports.
- ESM, CommonJS, and declaration entry points remain aligned.
- Package-root exports remain intentional, and private subpath imports remain
  rejected.
- `"use client"` is preserved in the distributed entry points.
- React, React DOM, Three.js, and React Three Fiber remain external peer
  dependencies, with unchanged ranges.
- The package has zero runtime dependencies and no import-time browser-global
  requirement.

### Package output and tree-shaking evidence

The released v2.9.0 artifact and its local release artifact were byte-identical
at that release baseline. Package contents, raw output sizes, compression,
peer externalization, `sideEffects: false`, and representative tree-shaking
were measured. This is bounded, one-time evidence; it does not establish an
exact-byte budget, a permanent size service, or a guarantee for every bundler.

### Consumer and compatibility policy

Consumer documentation distinguishes declared peer ranges from exact exercised
configurations, React and DOM responsibilities from Canvas-bound R3F work, and
package-root imports from private paths. Browser smoke evidence is bounded and
non-certifying. Vite and Next.js Client Component guidance states the exercised
boundaries without promising broad framework, router, deployment, browser,
accessibility, or LTS certification.

### Legacy and deprecated options

The five current legacy or deprecated public options remain available:

- `transitionDurationMs`
- `cooldownMs`
- top-level `easing`
- `nextKeys`
- `prevKeys`

The three timing options remain supported compatibility surface. The existing
machine-readable deprecation of `nextKeys` and `prevKeys` is preserved. No
option was removed, and no migration is required.

### Post-v2.10.0 maintenance direction

The v2 line continues with focused, compatible, evidence-backed maintenance.
This release creates no v3 milestone, roadmap, or commitment. Future major
planning requires a separately confirmed breaking requirement and explicit
owner approval.

### Compatibility and migration

- The completed v2.9.0 navigation-acceptance behavior remains authoritative.
- Public snapshots, `FlowFrameState`, `FlowProviderProps`, and all five legacy
  or deprecated options remain compatible.
- The package-root/private-subpath boundary remains unchanged.
- The seven runtime exports, zero runtime dependencies, peer dependencies and
  ranges, scripts, and CI remain unchanged.
- No migration is required.
