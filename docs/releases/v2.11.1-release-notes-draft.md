## GitHub Release draft

# r3f-interactive-flow v2.11.1

### Highlights

`v2.11.1` is a focused, backward-compatible touch-input robustness patch.
Accepted touch navigation already remained functional, so the defect was
non-fatal. The patch avoids ineffective prevention attempts and avoidable
Chromium intervention warnings for non-cancelable events.

No migration is required.

### Non-cancelable touch-event prevention

The patch corrects native-event prevention in three paths:

1. the first accepted threshold-crossing `touchmove`;
2. later committed `touchmove` events;
3. the accepted `touchend` fallback.

Cancelability controls only whether `preventDefault()` is called. It does not
control navigation acceptance, and an accepted non-cancelable event may still
navigate. `preventDefault: true` is not a guarantee that scrolling can always be
interrupted after the browser has committed scrolling.

### Preserved behavior

- One committed gesture still navigates at most once.
- Cancelable accepted events retain prevention.
- Rejected events remain unprevented.
- `preventDefault: false` remains unchanged.
- Provider cooldown and hook-local cooldown remain separate.
- Manual lock, transitions, phase boundaries, multi-touch invalidation,
  `touchcancel`, rerender behavior, retargeting, and cleanup remain unchanged.
- `useWheelInput` and `useKeyboardInput` behavior did not change.

### Compatibility and migration

This is a patch release. No public API or public TypeScript type changed. No
package export or subpath changed, no dependency or peer range changed, and no
option was added or removed. No migration is required.

### Validation evidence

- Focused tests in PR #479 cover all three corrected call sites.
- The full Node suite and browser input suite passed.
- Chromium delivered a genuine `cancelable === false` `touchmove`.
- The pre-fix red run emitted the intervention warning; the post-fix green run
  emitted no matching warning.
- One continuous committed gesture navigated exactly once.
- Exact-head GitHub Actions passed before merge.
- PR #480 aligned the public documentation with the corrected behavior.

No physical-device validation was performed for this exact fix. The controlled
evidence is Chromium-specific; it is not Safari, Firefox, WebKit, or
cross-browser certification. CDP delivery is not claimed to be internally
identical to manual Chrome DevTools responsive emulation.

### Published-consumer follow-up

The downstream Phase Field application identified the defect while consuming
exact `r3f-interactive-flow@2.11.0`. It remains pinned to `2.11.0` during release
preparation. After npm publication, a separate downstream task will upgrade the
exact pin to `2.11.1` and repeat the touch validation. This release-preparation
change does not claim that published `2.11.1` consumer validation has already
passed.
