# r3f-interactive-flow v2.9.0

v2.9.0 is a focused, backward-compatible correction to multi-touch handling
in `useTouchInput`. It prevents multi-touch sequences from being interpreted
as phase-navigation swipes while preserving existing single-touch behavior.

### Consumer-visible behavior

- Navigation is eligible only when a touch sequence begins with exactly one
  active touch.
- A sequence that starts or becomes multi-touch remains invalid until every
  touch ends, including after it returns to one active touch.
- Invalid multi-touch sequences do not navigate and are not
  default-prevented.
- After all touches end, a fresh single-touch gesture works normally.

### Compatibility and migration

- Existing one-touch behavior is unchanged.
- The public API, public TypeScript types, package exports, runtime
  dependencies, peer dependency ranges, and root-only package boundary are
  unchanged.
- No migration is required for existing v2 consumers.

### Implementation evidence

Issue #457 defined the multi-touch safety correction, and PR #458 merged the
runtime behavior, deterministic hook tests, bounded Chromium browser coverage,
and matching input-handling documentation. The merged evidence covers
multi-touch at sequence start, a second touch joining later, sticky
invalidation until all touches end, no navigation or prevention for invalid
sequences, and acceptance of a fresh later single-touch swipe.

### Validation evidence
