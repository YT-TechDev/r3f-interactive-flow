# r3f-interactive-flow v2.8.0

v2.8.0 is a transition-contract completeness minor release. It validates and
documents the existing transition lifecycle, records an evidence-backed
no-change decision for source/target transition metadata, and aligns
user-facing documentation with the confirmed runtime contract, while
preserving the stable v2 runtime API, public types, package exports,
dependencies, and peer dependency ranges.

### Highlights

- Records the transition-semantics audit from #395 / PR #439.
- Records snapshot timing and provider-clock evidence from #396 / PR #442.
- Records non-adjacent `goTo()` and `byPhase` evidence from #397 / PR #443.
- Records easing, zero-duration, cooldown, and lock composition evidence
  from #398 / PR #444.
- Records the source/target metadata no-change decision from #399 / PR #445.
- Records public documentation alignment from #400 / PR #446.

### Transition contract

Accepted `next()`, `prev()`, and `goTo()` navigation with positive duration
updates `phase` and `phaseIndex` to the target synchronously and resets
`progress` to `0`. `progress`, `direction`, and `isTransitioning` follow a
deterministic lifecycle from accepted navigation through raw completion,
where raw elapsed time, not eased public progress, decides completion.
Finite custom easing output is clamped before becoming public progress.
Zero-duration transitions complete synchronously in the same call. Lock and
provider-cooldown composition remain independent of each other and of
transition state. The provider owns the only machine-advancing clock;
`useFlowFrame` remains a read-only observer, and React and R3F sampling are
separate paths over the same provider-owned machine, not promised to occur
at the exact same instant.

### Direct `goTo()` and `byPhase`

Forward and reverse non-adjacent `goTo()` calls resolve in one direct
transition with no intermediate phase visitation or queueing; direction is
derived from relative indexes. `transition.byPhase` resolves from the source
phase, with independent per-field fallback:
`byPhase -> transition global -> legacy top-level -> default`. Same-phase
requests and known rejected navigation remain mutation-free no-ops. Unknown
`goTo()` targets throw before the normal rejection path.

### Metadata decision

r3f-interactive-flow will not add `sourcePhase`, `targetPhase`, or
`previousPhase` to `FlowSnapshot`, `FlowControls`, or `FlowFrameState` in
v2.8.0. The current public API plus application-owned previous-phase
observation, demonstrated for React and R3F usage, is sufficient for the
non-adjacent scenarios evaluated in this milestone. This decision avoids
permanently expanding the stable public contract without demonstrated need.
Future reconsideration requires a concrete evidence-backed scenario and a
separately approved Issue; this decision does not reserve a field name or
promise a future addition.

### Documentation and usage guidance

The root README, the distributed package README, the core-concepts guide,
the R3F usage guide, and the common-mistakes guide are aligned with the
confirmed transition contract. This includes the React Effect-owned
committed observation pattern, R3F frame-local ref observation inside
Canvas-bound components, and the zero-duration completion-observation
caveat where `direction` returns to `"none"` in the same call that accepts
the transition.

### Runtime and API changes

- No package runtime source changes are included in the v2.8.0 milestone
  work.
- No public API or public production-type changes are included.
- No package export or package-subpath changes are included.
- No runtime dependency or peer dependency range changes are included.
- No migration is required for existing v2 consumers.

This release is primarily contract validation, a recorded decision, and
documentation alignment rather than a runtime or API change.

### Repository maintenance

`actions/checkout` is pinned to `7.0.1` in CI and release workflows, and root
and example development-tool dependencies received patch/minor updates with
an associated root lockfile update. These are repository maintenance and
development-tooling changes only; they do not affect the package's
distributed runtime dependencies.

### Compatibility

- React, React Three Fiber, and Three.js peer dependency ranges remain
  unchanged.
- The package's root-only export boundary remains unchanged.
- ESM and CJS runtime and declaration output paths remain intentional and
  unchanged.
- Existing v2 consumers require no migration.

### Evidence boundaries

v2.8.0 does not introduce or promise:

- source/target transition metadata;
- accepted-navigation callbacks or lifecycle event emitters;
- transition queues or interruption;
- route-pair configuration, graphs, or timelines;
- router integration;
- a visual interpolation framework;
- exact same-instant React/R3F sampling guarantees;
- support for relying on non-finite easing return values as a stable
  contract.
